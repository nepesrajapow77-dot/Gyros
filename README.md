# Касса кафе — веб-приложение

Учёт кассы, питания сотрудников, авансов, общей налички и зарплаты для нескольких точек (кафе).
Этот файл — инструкция для разработчика или ИИ-ассистента, который будет менять приложение.

- Приложение бухгалтера (ввод данных): https://nepesrajapow77-dot.github.io/Gyros/
- Приложение начальника (только просмотр): https://nepesrajapow77-dot.github.io/Gyros/boss.html

Интерфейс и все тексты — на русском. Пользователи не программисты: объясняйте им просто и по шагам.

## Как устроено

Статический сайт без сборки и без зависимостей: чистые HTML, CSS и JavaScript.
Хостинг — GitHub Pages (ветка `main`, корень репозитория). Облако — Firebase (Authentication + Firestore), проект `gyros-c438c`.

| Файл | Что внутри |
| --- | --- |
| `index.html` | Приложение бухгалтера. Задаёт `window.VIEWER = false` и подключает скрипты |
| `boss.html` | Копия `index.html` с `window.VIEWER = true`, синим цветом и своим манифестом |
| `app.js` | Вся логика: данные, расчёты, экраны, формы, фото. Обычный скрипт (не модуль) |
| `sync.js` | Синхронизация с Firebase (ES-модуль, SDK 10.12.2 с gstatic). Экспортирует `window.Sync` |
| `firebase-config.js` | `window.FIREBASE_CONFIG`. Если `null` — облако выключено, всё работает локально |
| `app.css` | Стили, светлая и тёмная тема через CSS-переменные |
| `sw.js` | Service worker: офлайн-кэш (сначала сеть, без сети — кэш) |
| `manifest.webmanifest`, `boss.webmanifest`, `icon*.svg/png` | Установка на телефон (PWA) |

Экраны (нижнее меню): **День** (по точке и дате: касса, чек и кто ел, аванс, фото за день),
**Наличка** (общая на все точки, по дате, плюс итог за месяц), **Зарплата** (по месяцу), **Ещё** (точки, сотрудники, облако, резервная копия).

## Данные

Локально всё хранится в `localStorage` под ключом `buh.v1` (у начальника `buh.view.v1`) как один объект `db`.
Фото хранятся отдельно в IndexedDB (`kassa-photos` / `kassa-view-photos`).
Даты — строки `YYYY-MM-DD`. Суммы — числа. У каждой записи есть `id` (строка) и `updatedAt` (мс).

| Коллекция | Поля |
| --- | --- |
| `points` | `name` |
| `employees` | `name`, `position`, `pointId`, `salary` (в месяц), `archived` (уволен) |
| `registers` | `date`, `pointId`, `register` (счёт кассы), `check` (чек на питание) |
| `food` | `date`, `pointId`, `employeeId` (`'__boss'` = «Знакомые начальника»), `amount` |
| `advances` | `date`, `pointId`, `employeeId`, `amount` |
| `cash` | `date`, `pointId` (пусто — наличка общая), `cash`, `added`, `expense`, `note` |
| `photos` | `date`, `pointId`, `cashId` (если фото чека к записи налички) |

Служебное в `db`: `deleted` — пометки удаления для синхронизации, `sync` — что уже получено из облака.

Расчёты (в `app.js`):
- касса точки за день = `register − check`;
- общая наличка = нарастающий итог `cash + added − expense − advances` по всем точкам (`cashTimeline`);
- к выдаче сотруднику за месяц = `salary − питание − авансы` за этот месяц;
- «Знакомые начальника» в зарплату не входят, считаются отдельно;
- чек дня разделён полностью, когда сумма `food` за день и точку равна `check`.

## Облако и синхронизация

Firestore: `biz/main/{коллекция}/{id}`, документ = запись как есть.
Удаление = документ с `{ id, deleted: true, updatedAt }` (настоящих удалений нет).
Фото: метаданные в `photos`, сама картинка (JPEG base64, до ~700 КБ) — в `photoData/{id}`; грузится по запросу (`Sync.getPhoto`).

- Бухгалтер отправляет записи, у которых `updatedAt > syncedAt` (пакетами), и фото из очереди IndexedDB.
- Оба приложения слушают изменения новее последнего полученного `updatedAt` по каждой коллекции.
- Конфликт решается так: побеждает запись с большим `updatedAt` (`applyRemote`).
- Без интернета всё сохраняется локально и отправляется при следующем открытии с сетью.

Доступ задают правила Firestore (меняет владелец в консоли Firebase → Firestore → Rules → Publish):
писать может только почта бухгалтера, читать — бухгалтер и начальник; разрешённые коллекции перечислены списком.
**Новую коллекцию нужно добавить и в `COLS` в `app.js`, и в список в правилах, иначе запись будет отклонена.**

## Как вносить изменения

1. Правьте файлы. Проверьте локально через любой статический сервер в этой папке, например `python -m http.server 8000`
   (облако на localhost работает, но вход нужен настоящий).
2. Поднимите версию, чтобы телефоны получили обновление: в `index.html`, `boss.html` и `sw.js` замените `?v=N` на `?v=N+1`,
   а в `sw.js` — `const CACHE = 'kassa-vN'` на следующий номер.
3. `git commit` и `git push` в `main`. GitHub Pages обновится за 1–2 минуты.
4. Пользователю: полностью закрыть приложение и открыть снова.

Правила:
- Не ломайте сохранённые данные: новые поля добавляйте с безопасными значениями по умолчанию, старые записи приводите в `normalizeDb`.
- Начальник только смотрит: всё, что меняет данные, скрывайте при `VIEWER` и добавляйте действие в `EDIT_ACTS`.
- Не перерисовывайте экран, пока человек печатает (используйте `safeRender`).
- Каждое изменение записи — через `stamp(rec)`, удаление — через `removeRec(col, rec)`, иначе синхронизация его не увидит.
- Никогда не коммитьте пароли. Конфиг Firebase публичный по задумке — защищают правила Firestore.
- Репозиторий публичный: не пишите сюда почты, имена и суммы из реальных данных.

## Доступ для нового разработчика или ИИ

Доступ даёт только владелец, сам:
- **код** — GitHub → репозиторий Gyros → Settings → Collaborators → Add people (или подключить ИИ-сервис к GitHub через его кнопку «Connect GitHub»);
- **облако** — Firebase → Project settings → Users and permissions → Add member (обычно хватает роли Viewer);
- правила Firestore и пользователей входа меняет владелец в консоли Firebase.
